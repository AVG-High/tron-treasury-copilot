# 계획 변화 관측과 수익 표시 경계

`포지션·회고`에서 확인한 **실시간 기본 계획**을 관측한다. 데모·스트레스 결과·수정 후 미확인 조건은 관측 대상으로 사용하지 않는다. 자동 조회는 기본 OFF이고 사용자가 켜면 1/5/15분 간격으로 조회한다. 브라우저를 새로고침하면 OFF로 돌아간다.

## 관측하는 것

- 원래 선택한 배분과 현재 기본 APY를 **같은 원금과 원래 전체 운용 기간**으로 비교한다. 기본 이자 변화만 비교하며 인센티브·비용을 합산한 실제 수익이라고 표시하지 않는다. 기본 APY 0은 유효하지만 결측은 `확인 불가`다.
- 현재 지갑 USDT가 예정 지출·비상금·원래 왕복 비용 예약을 충족하는지 확인한다. 이미 지출한 비용은 전체 원장이 없어 자동 공제하지 않으므로 보수적인 부족 알림이 발생할 수 있다.
- 보유 자산별 시장 현금과 포지션 수량을 비교한다. USDD의 시장 현금은 USDD 수량 기준이며 USDT 환전·즉시 출금 보장이 아니다.
- 차입이 있는 계정, 검증되지 않은 데이터, 토큰 주소 변화, USDD 전환 경로 미지원 등을 알린다.
- 원계획 생성 시각부터 지난 **24시간 단위**로 잔여 기간과 예정 지출일을 이동한다. 자정 통과만으로 하루가 지나지 않는다. 날짜가 도래한 지출도 사용자가 지급 완료를 확인하기 전 전액 예약한다.

## 조회 생명주기

한 자동 조회가 끝난 뒤 다음 타이머를 예약하므로 같은 루프의 요청을 겹치지 않는다. 브라우저 문서가 보이지 않을 때는 새 조회를 건너뛴다. 다시 보이면 다음 예약 시점에 조회한다. 다른 앱 탭으로 가거나 노트북이 잠들면 계속 실행되는 서버 봇이 아니다. 제품 내부 메뉴 이동은 관측을 유지한다.

실패하면 지연을 두 배로 늘리되 최대 15분으로 제한한다. 세 번째 연속 실패 시 자동 조회를 끄고 재시작을 기다린다. 성공하면 선택한 기본 주기로 돌아간다. 마지막 성공 시점에서 5분이 지나거나 최근 조회가 실패하면 재검토 버튼이 이전 값을 최신으로 사용하지 못하도록 막는다.

계획·배분·연결 계정이 바뀌거나 입력이 미확인 상태가 되면 기존 관측을 중지한다. 거래 준비·서명 등 작업 중에도 잠시 멈춘다. 중지한 요청의 늦은 응답은 폐기한다. 수동 관측은 요청 한 번으로 소비하며 자동 OFF에서 주기 변경이나 일시 정지 해제만으로 다시 실행하지 않는다.

## 재검토 흐름

`남은 기간 조건 검토`는 원래 계획 총자금을 유지한 새로운 입력을 연다. 기존 포지션을 회수하거나 재예치하지 않는다. 사용자는 실제 가용 자금과 이미 지급한 지출을 수정하고 다시 계산해야 한다. 자금 대부분이 이미 예치돼 있다면 원래 총자금을 그대로 새 예치 가능액으로 사용할 수 없으며, 기존 실행 검증이 현재 지갑의 현금 한도를 다시 확인한다.

원래 운용 기간이 만료됐거나 현재 시장 스냅샷의 시각을 검증할 수 없으면 제안을 만들지 않는다. 화면의 제안은 이동 비용까지 검증한 리밸런싱 실행 지시가 아니다.

저장 계획의 `조건 불러오기`도 저장 버튼을 누른 시각이 아닌 원래 계산 생성 시각에서 기간을 차감한다. 운용 기간이 만료됐으면 입력값 0과 안내를 보여주며 사용자가 새 기간을 입력할 때까지 계산 검증을 통과할 수 없다. 저장 기록 자체나 과거 가정은 수정하지 않는다.

## 포지션 기록과 실제 수익

지갑 스냅샷은 별도 키 `tron-treasury-copilot-observations-v1`에 최근 96개까지 저장한다. 동일 지갑·시각 중복이나 역순 응답은 추가하지 않는다. 손상 데이터와 저장 실패는 알리고 원본을 덮어쓰지 않는다. 저장된 금액·주소는 이 브라우저의 편의 기록이며 서버 계정·인증 저장소가 아니다.

같은 지갑의 두 관측에서 포지션 기초자산 수량 차이를 보여줄 수 있다. jToken 수량 변화 여부를 함께 표시한다. 한쪽에 없는 포지션은 0으로 보정하지 않는다. **jToken 수량이 같아도 중간 예치 후 회수, 외부 이전, 보상, 비용이 없었다고 증명할 수 없으므로 실제 순수익은 산출 불가**다.

완전한 개인 성과 원장은 추후 확정 블록·전체 입출금 이벤트·jToken 이전·보상·실제 수수료·환산 가격·커버리지·재조직 처리를 포함해야 한다. 지금 저장한 거래 내역만 전체 이력이라고 가정하지 않는다. 기록 JSON에는 주소·잔고가 들어가므로 공개 시연 자료로 사용하지 않는다.

## 검증 근거

- `tests/monitor.test.ts`: 날짜·예약금·0/결측·주소·유동성·서로 다른 자산·원본 불변·수익 미산출.
- `tests/monitor-loop.test.ts`: 중복 조회 방지, 늦은 응답 폐기, 숨김 상태, 백오프·중지.
- `tests/observations.test.ts`: 정확한 숫자·null 보존, 손상/빈 기록 보호, 상한·중복·시각·저장 실패.
- `tests/monitoring.e2e.ts`: 모의 실시간 금리/지갑으로 알림·기록·조건 재검토·중지·모바일 표시 검증. 모의 지갑이므로 실자금 성공 증거가 아니다.
